# План тестирования DGCloak Admin + клиент

Состояние на старте: 7 лаб откачены к initial-снапшотам; в `data.json` все лабы помечены
`deployed=True`, ключи `keys\*_ed25519` прописаны, `sudo_mode=pw`. То есть **реестр
устарел** — это стартовая точка блока A.

Лабы: ubuntu20 .206 · ubuntu22 .210 · ubuntu24 .212 · ubuntu26 .213 · debian11 .214 ·
debian12 .215 · debian13 .200. Продакшн: dlmedia (ключ OpenSSH, sudo NOPASSWD),
london aws (ppk, порт 8081, sudo NOPASSWD; доступа к консоли AWS нет — **не ломать SSH**).

Отмечай: `[x]` ок · `[!]` баг (номер в разделе «Найдено») · `[-]` пропущен.

## A. Устаревший реестр vs чистый сервер (все лабы, до любого деплоя)

Цель: ни одна кнопка не должна упасть с трейсом или сделать вид, что всё хорошо.

- [ ] A1 **Проверить статусы** на чистой лабе → все шаги `…`/`✗`, `deployed` снимается, галочка ✓ в списке серверов пропадает.
- [ ] A2 **Импорт ключей** на чистой лабе → сначала probe, затем диалог «не развёрнут — сначала Развернуть всё». Без трейса.
- [ ] A3 **Пользователи → Обновить** на чистой лабе → внятная ошибка (нет admin_uid/pubkey), не трейс.
- [ ] A4 **Создать юзера** на чистой лабе → внятная ошибка, реестр юзеров не засоряется.
- [ ] A5 **Сбросить сервер** на чистой лабе → purge отрабатывает идемпотентно (rc=0, ничего не удаляет лишнего), реестр чистится.
- [ ] A6 **Перезагрузить сервер** на чистой лабе → ребут проходит, «сервер поднялся», флаг reboot не трогается.
- [ ] A7 **Управление фаерволом** на чистой лабе → либо список правил (ufw/nft/iptables что есть), либо внятное «фаервол не настроен».
- [ ] A8 Мёртвый ключ: лог показывает `ключ отвергнут сервером — работаю по паролю`, операция продолжается по паролю без промпта/зависания.
- [ ] A9 Debian11/12/13 без sudo: шаг 1 падает с подсказкой `su -` / `apt install sudo` / `/usr/sbin/usermod -aG sudo labadmin` — имя юзера из карточки сервера. После выполнения в консоли VM деплой идёт без переподключения вручную.

## B. Деплой — 7 дистрибутивов

На каждой лабе: **Развернуть всё** одним нажатием с чистого состояния.

- [ ] B1 ubuntu20 · [ ] B2 ubuntu22 · [ ] B3 ubuntu24 · [ ] B4 ubuntu26 · [ ] B5 debian11 · [ ] B6 debian12 · [ ] B7 debian13
  Для каждого: все 9 шагов ✓/⚠; спиннер крутится на активном шаге и только в таблице этого сервера; лог идёт живьём в deploy-канал; по окончании `=== Проход завершён ===`.
- [ ] B8 Reboot-required: на лабе с обновлённым ядром появляется диалог «перезагрузить сейчас?». **Да** → сервер уходит, шаг 5 становится ✓ «reboot отправлен». **Нет** → шаг 5 остаётся ⚠, кнопка «Перезагрузить сервер» потом снимает ⚠ → ✓.
- [ ] B9 Повторный **Развернуть всё** на развёрнутом → все шаги пропущены за секунды, ничего не сломано (идемпотентность). Cloak/OpenVPN не перезапускаются без нужды.
- [ ] B10 **Только выбранный шаг** — отдельно шаг 4 (фаервол), шаг 9 (cloak) на развёрнутом → идемпотентно; шаг 7 (ovpn) → PKI не пересоздаётся («уже есть, пропускаю генерацию»).
- [ ] B11 Ключевая авторизация: после шага 2 карточка сервера получила `key`, следующие шаги идут по ключу; `sudo_mode` переключился на `np`, если установлен NOPASSWD, иначе остался `pw` — и всё работает в обоих режимах.
- [ ] B12 Per-server поля: поменять домен/протокол/порт на сервере A, переключиться на B и обратно → значения A сохранились, у B свои.
- [ ] B13 Деплой с **proto=tcp** на одной лабе (например ubuntu20) и **Cloak порт ≠ 443** (например 8443) на другой → всё проходит, probe показывает `tcp/8443`, фаервол открыл нужный порт, юзер потом подключается.
- [ ] B14 Деплой при **занятом 443** (поставь на лабе `nginx` до деплоя) → шаг 9 даёт внятную ошибку «порт занят», а не молча падает.
- [ ] B15 Разрыв SSH посреди шага (выключи VM на шаге 5–6) → операция завершается ошибкой, lock снимается, кнопки оживают, следующий деплой продолжает с упавшего шага.

- [ ] C2 **Импорт ключей** на развёрнутом (деплой был этой же админкой) → «ключи подтянуты», pubkey/admin_uid/proto/mask_domain в реестре совпадают с сервером.
- [ ] C3 Полный цикл переезда: создать 2 юзеров → **Удалить сервер** из списка (бандлы в AppData удалились, `keys\` остались) → **Добавить** заново тот же хост/логин/ключ → **Импорт ключей** → «юзеров восстановлено: 2» → таблица с именами, маскировкой, лимитами; **Отозвать** одного из них работает (CN известен).

## D. Пользователи

- [ ] D1 Создать с дефолтами → одна строка в логе `Юзер «x» создан, выдай конфиг юзеру: <полный путь .dgcloak>`; служебные строки видны только с галочкой «Подробный вывод».
- [ ] D2 **Дубль CN** → ошибка «уже существует», ничего не создано, сертификат не перевыпущен.
- [ ] D3 Невалидный CN (`Иван`, `a b`, пусто) → ошибка валидации в диалоге.
- [ ] D4 Нечисловые значения в сроке/подключениях/лимите/квоте → ошибка валидации, диалог не закрывается.
- [ ] D5 Срок 1 день → «Истекает» = завтра; срок 0 → 2033. Истёкший юзер (поставь срок 1 день, переведи часы сервера на +2 дня или подожди) → клиент не подключается, в логе ck-client `User has expired`.
- [ ] D6 **Макс. подключений = 1** → подключить клиент с ПК, потом второй экземпляр (другой ПК/VM) с тем же конфигом → второй отваливается (`Sessions cap`).
- [ ] D7 **Лимит скорости** 2 Мбит/с ↓ → speedtest через туннель показывает ~2 Мбит/с. Лимит 0 → безлимит (таблица `∞`).
- [ ] D8 **Квота** 20 МБ ↓ → скачать 50 МБ через туннель → сессия терминируется, в таблице остаток квоты падает (`↓0M`), повторное подключение отказано. Квота 0 → `∞`.
- [ ] D9 **Изменить…**: сменить лимит/квоту/срок/домен → PUT прошёл (или DELETE+POST фолбэк на старом API — проверить в логе), таблица обновилась, `.dgcloak` перевыпущен с новым `ServerName`; CN в диалоге readonly.
- [ ] D10 Per-user домен: два юзера с разными доменами → в `.dgcloak` разные `ServerName`; оба подключаются; серверный `RedirAddr` не менялся.
- [ ] D11 **Отключить сейчас** на онлайн-юзере → клиент отваливается в течение секунд, лог `Сессия сброшена`; на офлайн → `не онлайн — сбрасывать нечего`.
- [ ] D12 **Отозвать и удалить** на онлайн-юзере → сертификат в CRL, UID удалён, сессия сброшена, папка бандла в AppData удалена, `users.json` на сервере без него; клиент с его конфигом больше не подключается (TLS error / auth fail).
- [ ] D13 **Экспорт конфига…** в произвольную папку → `<папка>\<cn>\<cn>.dgcloak`, импортируется в клиент, подключается.
- [ ] D14 Таблица: «Сессий»/«Онлайн» по центру; «●» появляется у подключённого после **Обновить**, пропадает через ~2 мин после отключения клиента (keepalive).
- [ ] D15 Переключение серверов во время операции на другом → таблица/лог не затираются чужими данными; после завершения выбранный сервер показывает своё.

## E. Логи и UI

- [ ] E1 Два канала: деплой пишет только в лог вкладки «Развёртывание», юзер-операции — только во вкладку «Пользователи». Запустить деплой, переключиться на «Пользователи» → там пусто/своё.
- [ ] E2 «Подробный вывод» ретроспективно: создать юзера с выключенной галочкой → включить → появились `user-cert.sh…`, `ck-client: …info`; выключить → исчезли. Ошибки/warn видны всегда.
- [ ] E3 Логи per-server: переключение серверов показывает свой журнал, деплой на A при выбранном B пишет в A (с пометкой «идёт операция на A»).
- [ ] E4 **Копировать лог** → буфер содержит ровно видимый текст.
- [ ] E5 Lock: во время операции все кнопки disabled, попытка нажать → «Идёт другая операция»; после завершения/ошибки — enabled.
- [ ] E6 Диалог сервера: выбрать `.pub` → подставился приватный; вписать `.pub` без пары → ошибка. Порт 0/70000/буквы → ошибка. Без ключа и пароля → ошибка.
- [ ] E7 Ctrl+C/V/X/A в полях при русской раскладке (оба приложения).
- [ ] E8 Окно 1040×680 не ресайзится; на 100% и 125% DPI всё влезает (Cloak порт у правого края, кнопки ровные).
- [ ] E9 Второй экземпляр админки → отказ «уже запущена».
- [ ] E10 Закрыть админку во время `ck-client -a` → процесс не остаётся сиротой (`tasklist | find "ck-client"` пусто).

## Что поднять дополнительно (идеи)

1. **Лаба с root-входом** (PermitRootLogin yes, без sudo-юзера) — путь `sudo=""` ни разу не гонялся на деплое целиком.
2. **Лаба с нестандартным SSH-портом** (2222) и **с активным ufw до деплоя** с правилом `deny 443` — проверить, что фаервол-шаг не выпиливает ssh и открывает нужное.
3. **Лаба с `iptables-persistent`** вместо nftables/ufw (Debian с установленным пакетом) — третий бэкенд фаервола.
4. **Лаба с nginx на 443** — для B14.
5. **Чистая Windows-VM** без OpenVPN/PuTTY/Git — установить только `DGCloakVPN.exe` и `DGCloakAdmin\` → проверить сообщения о недостающих зависимостях и автоскачивание ck-client; на ней же — «переезд админки» (C3 в чистой среде).
6. **Второй клиент-девайс** (Android с Cloak+OpenVPN или вторая Windows-VM) — для D6 (Sessions cap) честно нужен второй экземпляр.
7. **Малая квота** требует измеримого трафика — удобно иметь на лабе `python3 -m http.server` с файлом 100 МБ, качать через туннель `curl` по внутреннему IP.
