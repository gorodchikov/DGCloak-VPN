DGCloak VPN — руководство пользователя

Windows-клиент DGCloakVPN и админка DGCloakAdmin: OpenVPN поверх Cloak (маскировка под HTTPS).

1. Что это

Комплект из двух Windows-программ для самостоятельного развёртывания VPN-сервера:

ПрограммаНазначение
DGCloakAdmin.exe Админка. Ставит на чистый Linux-VPS связку OpenVPN + Cloak по SSH (без Docker, напрямую пакетами), управляет пользователями: создание, лимиты, квоты, отзыв, мгновенное отключение, выгрузка готовых конфигов.
DGCloakVPN.exe Клиент для конечного пользователя. Поднимает локальный прокси Cloak, через него — OpenVPN. Профили, трей, автопереподключение, полный или раздельный туннель.
openvpn.exe ──TCP──► 127.0.0.1:<локальный порт> ──ck-client──► сервер:443 (выглядит как HTTPS) ──► ck-server ──► openvpn-server

Снаружи видно только TLS-подобный трафик на порт Cloak (обычно 443) — Cloak «маскируется» под обращение к домену маскировки. Для DPI соединение неотличимо от обычного HTTPS.

Поддерживаемые серверы: Ubuntu 20.04 / 22.04 / 24.04 / 26.04, Debian 11 / 12 / 13. Фаерволы: nftables, ufw, firewalld, iptables — определяются автоматически.
Клиентская ОС: Windows 10 / 11, только x64 (Server 2016+ тоже подойдёт). Windows 8.1 и старше не поддерживаются — нижнюю планку задают Python 3.14 и ck-client на современном Go.

2. Возможности

DGCloakAdmin

  • Развёртывание OpenVPN+Cloak на чистый VPS за один запуск — 9 шагов с журналом и статусами, готовые шаги пропускаются.
  • Работа с занятым портом: определяет, кто слушает порт (systemd-сервис, docker-контейнер, процесс), предлагает загасить или выбрать другой порт.
  • Пользователи: имя (CN), срок жизни, макс. сессий, лимит скорости ↑/↓, квота трафика ↑/↓, свой домен маскировки на каждого юзера.
  • Мгновенное отключение живой сессии, отзыв сертификата + удаление из Cloak.
  • Экспорт единого файла .dgcloak — пользователь импортирует его в клиент одним полем.
  • Импорт ключей с уже настроенного сервера (миграция/переезд на новый ПК).
  • Управление фаерволом сервера: список открытых портов, открыть/закрыть.
  • Вернуть сервер: откат к состоянию до деплоя по снимку — восстанавливает заглушенные сервисы и docker-контейнеры, исходный фаервол, не трогает чужие пакеты и SSH-доступ.
  • Два журнала на сервер (деплой / юзеры), язык интерфейса RU/EN на лету.

DGCloakVPN

  • Один файл-профиль .dgcloak (или пара ck-config + .ovpn).
  • Полный туннель или split-tunnel; обходной маршрут до сервера Cloak — автоматически.
  • Автопереподключение при обрыве, мониторинг процессов, статистика скорости/трафика в статусе и в трее.
  • Определение внешнего IP до и через VPN (3 сервиса с фолбэком).
  • Автоустановка зависимостей при первом запуске: OpenVPN через winget, свежий ck-client с GitHub.
  • Журнал с ротацией (текущий + предыдущий запуск), отладочный лог OpenVPN.
  • Трей: переключение профилей без окна, менюшка Disconnect/смена профиля.
  • Язык интерфейса RU/EN, запоминается.

3.3 Вкладка «Развёртывание»

ЭлементЧто делает
Домен для маскировки Домен по умолчанию для новых юзеров этого сервера (www.bing.com из коробки). У каждого юзера может быть свой.
Протокол OpenVPN udp (быстрее, по умолчанию) или tcp (с пометкой «TCP медленнее»). Блокируется после деплоя — смена требует перевыпуска конфигов юзеров.
Cloak порт Порт, на котором слушает ck-server (обычно 443). Если занят — деплой предложит загасить владельца или выбрать другой. Блокируется после деплоя.
Таблица шагов 9 шагов деплоя (см. раздел 5), статус и комментарий к каждому. У активного шага в статусе крутится дуга-спиннер.
▶ Развернуть всё Полный деплой сверху вниз; готовые шаги пропускаются. Перед прогоном — probe-сверка с сервером, чтобы устаревшая запись «всё ок» не пропустила шаги на откаченной машине.
Только выбранный шаг Точечный повтор одного шага после исправления ошибки.
Проверить статусы Read-only аудит (probe.sh): сверяет реальное состояние и обновляет значки. Если сервер не отвечает — метка «развёрнут» снимается.
Управление фаерволом Окно открытых портов сервера: список, открыть/закрыть свой порт. Опасные порты (SSH, Cloak) при закрытии предупреждают.
Импорт ключей Забрать ключи и юзеров с сервера, настроенного вручную или другой копией админки. Ничего не переустанавливает; после импорта сервером можно управлять.
Вернуть сервер Откат к состоянию до деплоя (см. раздел 7).
Перезагрузить сервер sudo reboot с проверкой подъёма по uptime; нужно, если шаг «Обновление системы» помечен ⚠ нужна перезагрузка.
Копировать / Очистить лог Работают с каналом «деплой» текущего сервера. Журналы хранятся на диске — Admin\logs\<сервер>\<канал>.log, ротация в .old при 256 КБ — и не пропадают при перезапуске.
Язык: RU/EN на лету. Уже написанное в логе и заметки шагов остаются на прежнем языке (тултип по наведению напоминает).
? Справа вверху — открывает это руководство в браузере, на языке интерфейса.

Легенда статусов: ✓ готово · ⚠ предупреждение · ✗ ошибка · – пропущен · … не выполнялся.

3.4 Вкладка «Пользователи»

Таблица: Имя (CN) · Макс. сессий · Лимит ↑/↓ · Квота ↑/↓ · Истекает · Домен маскировки · Онлайн.

КнопкаЧто делает
Обновить Опрос сервера: UID из admin-API Cloak, лимиты из users.json, кто онлайн — из management OpenVPN.
Создать… Диалог нового юзера → сертификат OpenVPN + UID в Cloak; готовый конфиг сразу лежит в %APPDATA%\DGCloak\Admin\bundles.
Изменить… Лимиты/срок/маск-домен выбранного юзера; при смене параметров конфиг перевыпускается. Без изменений — сервер не трогается.
Отключить сейчас Рвёт живую сессию через mgmt-интерфейс OpenVPN. Юзер остаётся, может переподключиться.
Отозвать и удалить Revoke сертификата (CRL) + удаление UID из Cloak + сброс сессии. Необратимо.
Экспорт конфига… Сохраняет единый .dgcloak-файл юзера куда скажешь — его и отдаёшь пользователю.
☐ Подробный вывод Показывает/прячет служебные строки юзер-операций (ck-client, user-cert). Запоминается отдельно для каждого сервера.

У юзера, которого нет в реестре админки (чужой UID), отозвать сертификат нельзя — админка предложит только удалить UID из Cloak (новые подключения закроются, текущая сессия не трогается).

Автопередача в клиент. Если на этом ПК стоит клиент DGCloakVPN (есть папка %APPDATA%\DGCloak\VPN), создание юзера и перевыпуск конфига сразу кладут профиль юзер@сервер в его список, а отзыв — удаляет его. Появляется через пару секунд или при следующем запуске клиента. Если клиента нет — конфиг, как раньше, только в user_bundles\.

4. DGCloakVPN (клиент) — панели и кнопки

4.1 Первый запуск — мастер «Настройка программ»

Если не найдены openvpn.exe или ck-client.exe, окно предложит:

  • Установить автоматически — OpenVPN ставится через winget, свежий ck-client качается с GitHub в %APPDATA%\DGCloak\bin.
  • Указать пути вручную — свои exe.

При пустом списке профилей предложит добавить первый.

4.2 Главное окно

ЭлементЧто делает
Выбор профиля (список) Активный профиль; после подключения запоминается для следующего запуска.
+ / Изм. / Удал. Профили: добавить диалогом (см. 4.3), изменить, удалить (файлы в profiles\ подчищаются).

Выход Закрывает программу; при активном VPN спросит — отключится и выйдет. Крестик и «свернуть» прячут окно в трей.
Дополнительно ▾ Раскрывает лог и кнопки: Копировать лог, Очистить лог, Пути к Cloak и OpenVPN…, галочка Отладочный лог OpenVPN (--verb 4, применится при следующем подключении, настройка сохраняется между запусками) и три галочки поведения при старте: Запускаться вместе с Windows — автозапуск программы при входе в систему; Подключаться при запуске — выбранный профиль подключается сам при старте программы; Сворачивать в трей при запуске — программа стартует сразу в трее, не показывая окно (работает, только когда значок в трее доступен). Все три вместе дают полностью тихий автозапуск VPN в трее. Лог — журнал выбранного профиля: хранится на диске между запусками (VPN\logs\<профиль>\session.log, ротация в .old на 256 КБ), при переключении профиля показывается его журнал; строки активного подключения пишутся в журнал своего профиля. При ошибке панель раскрывается сама.
Язык: RU/EN. Подсказка по наведению: уже выведенные строки лога остаются на прежнем языке.

4.3 Диалог профиля

Два пути наполнения — на выбор:

  • поле DGCloak конфиг (.dgcloak) — один файл от админки, всё остальное подтянется само;
  • — ИЛИ — вручную: название + ck-конфиг (.json) + OpenVPN профиль (.ovpn).

Редкие настройки — под раскрывашкой «Дополнительно ▾»:

ПолеЗачем
Локальный порт Cloak (-l) Порт, где ck-client принимает OpenVPN (по умолчанию 1984). Строки remote в .ovpn перезаписываются на 127.0.0.1:порт.
Сервер Cloak (-s) / Порт сервера (-p) Переопределяют RemoteHost/RemotePort из ck-конфига — обычно пусто.
IP обхода туннеля Маршрут до сервера через основной шлюз, чтобы трафик самого Cloak не заворачивался в VPN-петлю. Пусто = резолвится из ck-конфига.
UDP-режим (-u) Cloak-транспорт по UDP. Подхватывается и из "UDP":true в ck-конфиге.
Весь трафик через VPN Полный туннель (redirect-gateway local def1) или split-tunnel — идут только маршруты, что прописал сервер.
Переподключаться при обрыве До 3 попыток с паузой, статус «Переподключение…».

Файлы профиля копируются в %APPDATA%\DGCloak\VPN\profiles\<имя> — исходники после сохранения можно удалить.

5. Пример: развёртывание сервера с нуля

Нужно: чистый VPS на поддерживаемой ОС (Ubuntu 20–26 / Debian 11–13), SSH-доступ (root или юзер с sudo — пароль или ключ).
  1. Запусти DGCloakAdmin → слева Добавить: имя, IP, SSH-порт, логин, ключ или пароль → сохрани.
  2. Выбери сервер → вкладка Развёртывание. Задай домен маскировки, протокол (udp) и порт Cloak (443). После деплоя они заблокируются — выбери сразу правильно.
  3. ▶ Развернуть всё. Шаги идут по таблице сверху вниз:
1. SSH-подключение      — auth, проверка root/sudo (sudo -S с паролем)
2. Ключевая авторизация — если заходили по паролю: генерирует ключ, ставит его
3. Аудит ОС и окружения — дистрибутив, пакеты, docker, занятые порты;
                          тут же пишется снимок predeploy.env (для «Вернуть сервер»)
4. Фаервол              — аудит бэкенда → установка/настройка (nftables/ufw/…)
5. Обновление системы   — apt full-upgrade (можно отказаться; может занять 10–30 мин)
6. Пакеты               — OpenVPN, Easy-RSA, nftables при надобности
7. OpenVPN + PKI        — Easy-RSA CA, сертификаты, server.conf, mgmt-интерфейс
8. Маршрутизация и NAT  — ip_forward, masquerade только для 10.8.0.0/24 + tun0
9. Cloak server         — ck-server, ключи, домен маскировки, юнит
  1. Если шаг Обновление системы закончится ⚠ нужна перезагрузка — жми Перезагрузить сервер (или согласуй диалог), потом снова ▶ Развернуть всё — пройденные шаги не повторятся.
  2. Если порт 443 занят — см. раздел 6: выбери «загасить владельца» или «другой порт».
  3. Все шаги ✓, у сервера в списке ✓ — сервер развёрнут. Вкладка Пользователи → Создать…: CN, срок, лимиты, маск-домен → готово, конфиг уже в bundles\.
  4. Экспорт конфига… → сохрани user1.dgcloak → передай пользователю.
  5. На стороне пользователя: DGCloakVPN → + → поле DGCloak конфиг (.dgcloak) → выбрать файл → Сохранить → Подключить. В статусе появятся VPN IP, аптайм и скорость.
Проверка: «Проверить статусы» сверит состояние с сервером в любой момент; в клиенте внешний IP через VPN должен совпасть с адресом сервера.

6. Если порт Cloak занят

Перед установкой ck-server админка проверяет владельца порта и действует по типу:

ВладелецЧто предложит
systemd-сервис (nginx и т.п.) «Загасить?» — systemctl disable --now. Согласие → Cloak встаёт на порт; отказ → предложит другой порт (откроется в фаерволе само).
docker-контейнер «Загасить?» — docker stop + --restart=no (контейнер НЕ удаляется). Отказ → другой порт.
Процесс без сервиса Автоматически не освобождается — только выбор другого порта.
SSH Гасить нельзя (умрёт управление) — только другой порт.

Заглушенные сервисы/контейнеры записываются в снимок — «Вернуть сервер» поднимет их обратно.

7. «Вернуть сервер» — что делает

При деплое админка пишет снимок /etc/dgcloak/predeploy.env до любых изменений. Откат по кнопке:

  • сносит Cloak, OpenVPN-конфиги, PKI, юзеров, наши unit-файлы и правила фаервола, локальные конфиги юзеров на этом ПК;
  • возвращает прежнего владельца порта: заглушенный сервис — enable --now, docker-контейнер — исходный restart-policy + запуск (с рестартом dockerd, если ruleset был флашнут);
  • восстанавливает исходный ip_forward, оригиналы строк ufw (sysctl/forward-policy/before.rules), masquerade/forward firewalld;
  • удаляет только пакеты, которые поставили мы; чужие — не трогает;
  • на чужом nftables пересохраняет /etc/nftables.conf — наша таблица не воскреснет после ребута.

Не трогает: SSH-доступ, твою учётку, чужие сервисы и пакеты, ключи в ~/.ssh.

9. Частые вопросы

Сервер молчит / SSH висит

Кнопка Стоп операцию убивает зависшую команду. Заголовок окна пульсирует «операция идёт N с». Провайдер может резать долгие SSH — проверь связь и повтори шаг.

«Предупреждение: вы управляете своим VPN-сервером»

Если админка запущена на ПК, где клиент подключён именно к этому серверу — она спросит перед мутирующими операциями (reboot/revert/deploy). Разрыв туннеля посреди деплоя = оборванная операция.

VPN IP: строки нет в статусе

Клиент не смог определить внешний IP (туннель ещё поднимался). Строка появится сама, когда один из трёх сервисов ответит; до конца так и не определился — строка скрывается, это нормально.

«Cloak остановлен — VPN не работает»

ck-client умер (зависший порт, антивирус). Клиент сам переподключится при включённом reconnect; иначе — Отключить/Подключить. Зависшие процессы с прошлого запуска добиваются по pids.json автоматически.

«127.0.0.1 не отвечает»

Аварийное завершение OpenVPN съело системный маршрут loopback — клиент сам его восстановит до/после сеанса; если предупреждение осталось, нужна перезагрузка ПК.

Язык сменил, а лог остался по-русски

Так задумано: переводятся интерфейс и новые строки. Старые записи лога и заметки шагов не переписываются (тултип на «Язык:» об этом же).

TCP или UDP?

UDP быстрее — по умолчанию он. TCP — если в сети режут/губят UDP. Меняется только до деплоя.

Юзер «истёк» / квота кончилась

Подключаться не сможет: admin-API Cloak отклоняет. Продлить — «Изменить…» у юзера (срок/квоты), конфиг перевыпустится сам.
