DGCloak VPN — User Guide

The DGCloakVPN Windows client and the DGCloakAdmin tool: OpenVPN over Cloak (HTTPS masquerade).

1. What it is

A pair of Windows applications for deploying your own VPN server:

ProgramPurpose
DGCloakAdmin.exe The admin tool. Installs OpenVPN + Cloak onto a clean Linux VPS over SSH (native packages, no Docker) and manages users: create, limits, quotas, revoke, instant disconnect, ready-to-use config export.
DGCloakVPN.exe The end-user client. Brings up a local Cloak proxy, then OpenVPN through it. Profiles, system tray, auto-reconnect, full or split tunnel.
openvpn.exe ──TCP──► 127.0.0.1:<local port> ──ck-client──► server:443 (looks like HTTPS) ──► ck-server ──► openvpn-server

From the outside only TLS-like traffic to the Cloak port is visible (usually 443) — Cloak masquerades it as access to a mask domain. To DPI the connection is indistinguishable from ordinary HTTPS.

Supported servers: Ubuntu 20.04 / 22.04 / 24.04 / 26.04, Debian 11 / 12 / 13. Firewalls: nftables, ufw, firewalld, iptables — detected automatically.
Client OS: Windows 10 / 11, x64 only (Server 2016+ works too). Windows 8.1 and older aren't supported — the floor is set by Python 3.14 and the modern-Go ck-client.

2. Features

DGCloakAdmin

  • One-shot deployment of OpenVPN+Cloak on a clean VPS — 9 steps with a journal and per-step statuses; completed steps are skipped.
  • Busy-port handling: detects who owns the port (systemd service, docker container, bare process) and offers to quench it or pick another port.
  • Users: name (CN), lifetime, max sessions, up/down speed limits, up/down traffic quotas, per-user mask domain.
  • Instant disconnect of a live session; certificate revocation + removal from Cloak.
  • Exports a single .dgcloak file — the user imports it into the client with one field.
  • Key import from an already-configured server (migration/new admin PC).
  • Server firewall management: list open ports, open/close your own.
  • Revert server: rolls back to the pre-deploy state using a snapshot — restores quenched services and docker containers, the original firewall, leaves foreign packages and SSH access alone.
  • Two journals per server (deploy / users), RU/EN UI switch on the fly.

DGCloakVPN

  • One profile file .dgcloak (or a ck-config + .ovpn pair).
  • Full tunnel or split tunnel; the bypass route to the Cloak server is handled automatically.
  • Auto-reconnect on drops, process monitoring, speed/traffic stats in the status block and tray.
  • External IP detection before and through the VPN (3 services with fallback).
  • First-run dependency setup: OpenVPN via winget, latest ck-client from GitHub.
  • Rotating journal (current + previous run), OpenVPN debug log.
  • Tray: switch profiles without the window, Disconnect / switch-profile menu.
  • RU/EN interface, remembered.

3.4 Users tab

Columns: Name (CN) · Max sessions · Limit ↑/↓ · Quota ↑/↓ · Expires · Mask domain · Online.

ButtonWhat it does
Refresh Queries the server: UIDs from the Cloak admin-API, limits from users.json, who's online from the OpenVPN mgmt interface.
Create… New-user dialog → OpenVPN certificate + UID in Cloak; the ready config is saved to %APPDATA%\DGCloak\Admin\bundles.

Auto-provisioning to the client. If the DGCloakVPN client is present on this PC (the %APPDATA%\DGCloak\VPN folder exists), creating a user or reissuing a config drops a user@server profile straight into the client's list, and revoking removes it. It shows up within seconds or on the next client start. Without a client the config stays in user_bundles\ as before.

4.3 Profile dialog

Two ways to fill it — pick one:

  • the DGCloak config (.dgcloak) field — one file from the admin tool, everything else is filled in;
  • — OR — manually: name + Cloak config (.json) + OpenVPN profile (.ovpn).

Rare settings live under the "Advanced ▾" expander:

FieldPurpose
Local Cloak port (-l) Where ck-client accepts OpenVPN (default 1984). remote lines in .ovpn are rewritten to 127.0.0.1:port.
Cloak server (-s) / Server port (-p) Override RemoteHost/RemotePort from the ck config — usually empty.
Bypass IP A route to the server via the main gateway so Cloak's own traffic doesn't loop into the VPN. Empty = resolved from the ck config.
UDP mode (-u) Cloak transport over UDP. Also picked up from "UDP":true in the ck config.
Route all traffic via VPN Full tunnel (redirect-gateway local def1) or split tunnel — only the routes pushed by the server.
Reconnect on drop Up to 3 attempts with a pause, "Reconnecting…" status.

Profile files are copied into %APPDATA%\DGCloak\VPN\profiles\<name> — the originals may be deleted afterwards.

5. Example: deploying a server from scratch

You need: a clean VPS on a supported OS (Ubuntu 20–26 / Debian 11–13), SSH access (root or a sudo-capable user — password or key).
  1. Run DGCloakAdmin → Add on the left: name, IP, SSH port, login, key or password → save.
  2. Select the server → the Deployment tab. Set the mask domain, protocol (udp) and Cloak port (443). They lock after deployment — pick them right the first time.
  3. ▶ Deploy all. Steps run down the table:
1. SSH connection     — auth, root/sudo check (sudo -S with password)
2. Key authorization  — if you logged in by password: generates and installs a key
3. OS/environment audit — distro, packages, docker, busy ports;
                          the predeploy.env snapshot is written here (for Revert)
4. Firewall           — backend audit → install/configure (nftables/ufw/…)
5. System update      — apt full-upgrade (can be declined; may take 10–30 min)
6. Packages           — OpenVPN, Easy-RSA, nftables as needed
7. OpenVPN + PKI      — Easy-RSA CA, certificates, server.conf, mgmt interface
8. Routing and NAT    — ip_forward, masquerade for 10.8.0.0/24 + tun0 only
9. Cloak server       — ck-server, keys, mask domain, systemd unit
  1. If the System update step ends with ⚠ reboot required — press Reboot server (or accept the dialog), then ▶ Deploy all again — finished steps won't repeat.
  2. If port 443 is busy — see §6: choose "quench the owner" or "another port".
  3. All steps ✓ and the server shows ✓ — deployed. Go to the Users tab → Create…: CN, lifetime, limits, mask domain → done; the config is already in bundles\.
  4. Export config… → save user1.dgcloak → hand it to the user.
  5. On the user's side: DGCloakVPN → + → the DGCloak config (.dgcloak) field → pick the file → Save → Connect. The status block shows VPN IP, uptime and speed.
Verify: "Check statuses" re-audits the server at any time; in the client the external IP through the VPN should equal the server address.

6. If the Cloak port is busy

Before installing ck-server the tool checks who owns the port and acts by type:

OwnerWhat it offers
systemd service (nginx etc.) "Quench it?" — systemctl disable --now. Agree → Cloak takes the port; decline → you're asked for another port (opened in the firewall automatically).
docker container "Quench it?" — docker stop + --restart=no (the container is NOT removed). Decline → another port.
Bare process Can't be freed automatically — you only pick another port.
SSH Must not be quenched (management would die) — another port only.

Quenched services/containers are recorded in the snapshot — "Revert server" brings them back.

7. "Revert server" — what it does

During deployment the tool writes a snapshot to /etc/dgcloak/predeploy.env before touching anything. The revert button:

  • removes Cloak, OpenVPN configs, PKI, users, our unit files and firewall rules, and the local user configs on this PC;
  • restores the previous port owner: a quenched service gets enable --now, a docker container gets its original restart-policy back and is started (with a dockerd restart if the ruleset was flushed);
  • restores the original ip_forward, the original ufw lines (sysctl/forward-policy/before.rules), firewalld masquerade/forward;
  • removes only the packages we installed; pre-existing ones are kept;
  • on a foreign nftables setup it re-dumps /etc/nftables.conf so our table doesn't resurrect after reboot.

Untouched: SSH access, your account, foreign services and packages, keys in ~/.ssh.

9. FAQ

Server silent / SSH hangs

The Stop operation button kills the hung command. The window title pulses "operation running for Ns". ISPs can cut long SSH sessions — check connectivity and retry the step.

"Warning: you're managing your own VPN server"

If the admin tool runs on a PC whose client is connected to that very server, it asks before mutating operations (reboot/revert/deploy). Losing the tunnel mid-deploy means a broken operation.

No "VPN IP" line in the status

The client couldn't determine the external IP (the tunnel was still coming up). The line appears once one of the three services answers; if it never does, the line stays hidden — that's normal.

"Cloak stopped — VPN down"

ck-client died (busy port, antivirus). With reconnect enabled the client reconnects by itself; otherwise Disconnect/Connect. Leftover processes from the previous run are killed via pids.json automatically.

"127.0.0.1 does not respond"

An abnormal OpenVPN exit ate the system loopback route — the client restores it before/after a session; if the warning persists, reboot the PC.

Language switched but the log stayed Russian

By design: the UI and new lines are translated. Old log entries and step notes are not rewritten (the "Language:" tooltip says the same).

TCP or UDP?

UDP is faster — it's the default. TCP if the network mangles UDP. Only changeable before deployment.

User "expired" / quota exhausted

They can't connect: the Cloak admin-API refuses. Extend via "Edit…" on the user (lifetime/quotas) — the config is reissued automatically.
