# DGCloak VPN — контекст проекта для ИИ-агента

Windows-клиент для связки **OpenVPN поверх Cloak**: сначала запускается локальный прокси `ck-client.exe` (Cloak),
затем консольный `openvpn.exe`, который подключается не к серверу напрямую, а к локальному порту Cloak.
Окно на tkinter, значок в системном трее, несколько профилей, статус из management-интерфейса OpenVPN.

Язык проекта: **русский** (интерфейс, комментарии, сообщения лога). Пользователь русскоязычный и общается по-русски.

> Этот документ описывает код на момент создания репозитория. **Источник истины — код**. Если документ расходится с кодом, верьте коду и поправьте документ.

## Предыстория (зачем это всё)

Серверы OpenVPN over Cloak раньше настраивались через Amnezia: в её 5-й версии OpenVPN убрали, в старой версии
работает плохо, управления пользователями нет. Цель проекта из двух частей:
1. **Windows-клиент** — этот код, работает и используется.
2. **Серверное management-приложение** — настройка серверов по SSH (см. раздел «Планы»), пока не начато.

Важно: изначально клиент пытались сделать поверх OpenVPN Connect, но у него нет CLI-команд подключения/отключения
и статуса, поэтому перешли на консольный `openvpn.exe` (community-версия) с management-интерфейсом.

## Архитектура клиента (`cloak_ovpn.py`)

### Данные и файлы на диске
- Папка данных: `%APPDATA%\DGCloakVPN\`
  - `data.json` — настройки и профили (только пути и параметры, **секретов нет**; ключи — в `.ovpn`/конфиге Cloak, копии которых лежат в `profiles\`).
  - `last.log` — лог текущего запуска; при старте переименовывается в `prev.log` (ротация: текущий + предыдущий). Пишется напрямую из рабочих потоков, поэтому доступен даже при зависании окна.
  - `runtime.ovpn` — копия пользовательского `.ovpn`, в которой все строки `remote` заменены на `remote 127.0.0.1 <port> <tcp-client|udp>` (порт из профиля). OpenVPN запускается с этой копией — править `.ovpn` вручную не нужно.
  - `profiles\<имя>\` — при добавлении/изменении профиля его файлы (`ck_config`, `.ovpn` и внешние ключи, на которые .ovpn ссылается — `ca`/`cert`/`key`/`tls-auth` и т.п.) копируются сюда (`import_profile_files`), в data.json пишутся новые пути; исходники пользователь может удалить. При удалении/переименовании профиля папка подчищается.
- Схема `data.json`:
```json
{
  "ck_client": "C:\\Tools\\Cloak\\ck-client-windows-amd64.exe",
  "openvpn_exe": "C:\\Program Files\\OpenVPN\\bin\\openvpn.exe",
  "last_profile": "Stockholm",
  "profiles": [
    {"name": "Stockholm", "ck_config": "D:\\...\\stockholm.json", "ovpn": "D:\\...\\stockholm.ovpn",
     "port": 1984, "server": "", "server_port": "", "bypass_ip": "",
     "udp": false, "full_tunnel": true}
  ],
  "language": "ru"
}
```
  Поле `imported` в старых профилях — устаревшее, игнорируется. Последний успешно подключённый профиль сохраняется в `last_profile` и выбирается при старте.

### Запуск процессов (поток подключения, `App._connect`)
Выполняется в рабочем потоке (`_run` → `threading.Thread`). Все подпроцессы запускаются с `CREATE_NO_WINDOW`,
`stdin=DEVNULL`; stdout и stderr объединены в PIPE и читаются отдельным потоком (`_pump`) в лог.

0. **Предполётные проверки:** `repair_loopback()` (добавляет системный маршрут `127.0.0.1/32`, если его нет; см. ниже),
   `loopback_ok()` (локальный TCP на 127.0.0.1 работает), `find_procs()` (через `tasklist` ищет уже запущенные `ck-client`/`openvpn` —
   если есть, отказ с PID), проверка, что локальный порт Cloak свободен.
1. **Cloak:** `ck-client.exe -c <ck_config> -l <port> [-s <server>] [-p <server_port>] [-u]`.
   Локальный порт задаётся флагом `-l` (в json-конфиге Cloak его **нет**). Затем ждём до 15 с, пока порт начнёт принимать TCP (`probe()`);
   в UDP-режиме порт проверить нельзя, просто пауза 3 с.
2. **OpenVPN:**
```
   openvpn.exe --config <APP_DIR\runtime.ovpn> --cd <папка исходного ovpn> --management 127.0.0.1 <случайный свободный порт>
               --disable-dco [--route <bypass_ip> 255.255.255.255 net_gateway]
               [--redirect-gateway local def1] [--verb 4]
   `runtime.ovpn` создаётся функцией `_runtime_ovpn`: remote из профиля (`port`), proto по галочке `udp`.
```
3. **Статус через management:** поток `_mgmt_loop` подключается к management-порту, шлёт `state on all`, разбирает строки состояний
   регулярным выражением `STATE_RE`; на `CONNECTED` выставляется `self.up` (Event) — основной поток подключения ждёт его до 60 с
   (с «пульсом» в лог каждые 5 с). Состояния → русский текст/цвет — словарь `STATES`.
4. После успеха: `self.active = профиль`, сохранение `last_profile`, запуск `_monitor` (раз в 2 с проверяет, живы ли процессы Cloak и OpenVPN;
   при падении статус красный). Если в выводе OpenVPN были «route add command failed» (`route_failed`), показывается предупреждение о правах администратора.

### Отключение (`_disconnect` → `_stop_all`)
Остановка монитора → `_stop_vpn` (команда `signal SIGTERM` через management для штатной очистки маршрутов; ждём 10 с, затем `terminate`/`kill`) →
`_stop_ck` (terminate/kill) → `_check_loopback` + `repair_loopback`. Жёсткое убийство OpenVPN оставляет мусорные маршруты — избегать.

### Потоки и интерфейс (важные правила)
- **Из рабочих потоков нельзя трогать tkinter напрямую.** Обновление интерфейса только через `self.ui(fn)` — очередь, которую разбирает `_drain` в главном потоке каждые 100 мс (устойчива к исключениям в отдельных колбэках).
- Лог: `self.say(msg)` пишет в `last.log` сразу и в виджет через очередь.
- Колбэки pystray выполняются в потоке трея → всегда оборачивать в `self.ui(...)`. Из потока трея читаются только простые атрибуты (`active`, `busy`, `cur_name`, `data["profiles"]`), не виджеты.
- Необработанные исключения в потоках и tk-колбэках пишутся в лог (`threading.excepthook`, `report_callback_exception`) — в exe без консоли иначе они невидимы.
- Окно фиксированного размера (`resizable(False, False)`); кнопка «Дополнительно» раскрывает лог, «Копировать лог»/«Очистить лог», «Пути к Cloak и OpenVPN…», галочку «Отладочный лог OpenVPN» (`--verb 4`), выбор языка. При ошибке панель раскрывается сама.
- Язык интерфейса: `data.json["language"]` = `ru`|`en`, переключение — комбобокс «Язык» в расширенной панели. Переводы — словарь `STRINGS_EN` (ключ — русская строка), `self.t(ru, **kw)`; лог и лог-файл остаются по-русски.
- Крестик и «свернуть» прячут окно в трей (`_hide_to_tray`). Выход: пункт «Отключить VPN и выйти из программы» в меню трея или кнопка «Выход» в окне (с подтверждением при активном VPN).
- Меню трея динамическое (`_tray_items`, пересобирается через `update_menu()` при смене статуса/профиля): «Открыть», «Подключить «name»» / «Отключить «name»», «Подключить ▸ профили, кроме текущего/подключённого (выбор при активном VPN = переключение на него)», «Отключить VPN и выйти из программы». Цвет плаща в трее = статус.
- Без `pystray`/`Pillow` программа работает без трея (`HAS_TRAY = False`), крестик тогда закрывает программу.

## Сетевая логика

```
openvpn.exe ──TCP──► 127.0.0.1:<порт Cloak> ──ck-client.exe──► (TLS-подобный трафик, TCP/443) ──► ck-server ──► OpenVPN-сервер
   (remote 127.0.0.1 <порт>)        локальный прокси                  маскируется под HTTPS
```
- Строки `remote` в `.ovpn` игнорируются: `_runtime_ovpn` подставляет `remote 127.0.0.1 <port> <proto>` из профиля (порт = `-l` Cloak, proto по галочке UDP). Порт в настройках профиля — единственное место, где он задаётся.
- Cloak слушает только `127.0.0.1`; OpenVPN думает, что подключается к серверу, а Cloak пробрасывает трафик на реальный сервер.
- **Обход туннеля для трафика самого Cloak.** При полном туннеле (`redirect-gateway def1`) трафик ck-client к реальному серверу нельзя заворачивать в VPN (петля). Нужен маршрут до IP сервера Cloak через основной шлюз:
  в `.ovpn` (`route <IP> 255.255.255.255 net_gateway`) или полем `bypass_ip` в профиле (добавляется аргументом `--route`).
- **Флаг `local` в `--redirect-gateway local def1` критичен.** Без него OpenVPN пытается создать обходной маршрут до `remote`, то есть до `127.0.0.1`, а при выходе удаляет его — вместе с **системным маршрутом loopback**.
  Следствие в живой системе: после отключения 127.0.0.1 переставал отвечать, Cloak «не поднимал порт», ломались другие программы (v2rayN), помогала только перезагрузка.
  Страховка поверх флага: `repair_loopback()` (`route ADD 127.0.0.1 MASK 255.255.255.255 0.0.0.0 IF 1` до и после сеанса; код возврата 0 = маршрута не было и он восстановлен).
- `--disable-dco`: DCO-драйвер плохо дружит с локальным прокси; нужен OpenVPN ≥ 2.6. На практике используется драйвер TAP-Windows6.
- Подключение занимает ≈6 с: туннель поднимается за секунду, маршруты добавляются через 5 с (штатный `route-delay`).
- Проверочное подключение программы к порту Cloak создаёт одноразовую сессию Cloak; строки Cloak `Failed to read first packet from proxy client: EOF` в логе безвредны.
- Management-порт OpenVPN слушает только localhost, **без пароля** (OpenVPN предупреждает об этом). Известный компромисс, кандидат на улучшение.
- Запускать TUN-режим v2rayN одновременно с этим VPN нельзя (конфликт виртуальных адаптеров и маршрутов).
- Профили с `auth-user-pass` (логин/пароль) **не поддерживаются** (запрос приходит в management как `>PASSWORD:`, сейчас только пишется в лог).

## Сборка и запуск на Windows

Требования:
- Windows 10/11, Python с python.org (3.8+, лучше 3.10+; нужен tkinter).
- `ck-client.exe` (Cloak, клиент) и **OpenVPN Community** (консольный `openvpn.exe`, не OpenVPN Connect) с драйвером TAP-Windows6; проверялось на OpenVPN 2.7.7.
- **Права администратора** (создание адаптера и маршрутов). Без них OpenVPN отвечает `Access is denied` на добавление маршрутов.

Запуск из исходников (от администратора):
```bat
pip install -r requirements.txt
python cloak_ovpn.py
```
Первый запуск (`_first_run`, через ~400 мс после старта): программа ищет `openvpn.exe` (PATH, Program Files) и `ck-client.exe` (папка данных, PATH), подставляет найденное в `data.json`; чего не хватает — показывается мастер `SetupDialog`: «Установить автоматически» ставит OpenVPN через `winget install OpenVPNTechnologies.OpenVPN` (есть в Win11 и обычных Win10; на LTSC/Server может отсутствовать — тогда ручная установка) и скачивает свежий `ck-client-windows-amd64*.exe` через GitHub API `releases/latest` в `%APPDATA%\DGCloakVPN`. Пути проверяются быстрым запуском (`exe_runs`, таймаут 10 с). Если профилей нет — предлагается добавить первый. Ручная смена путей: «Дополнительно» → «Пути к Cloak и OpenVPN…».

Сборка exe:
```bat
build.bat
```
Скрипт ставит `pyinstaller pystray pillow`, генерирует `app.ico` (`python cloak_icon.py app.ico`) и вызывает
`PyInstaller --noconsole --onefile --uac-admin --icon app.ico --version-file version_info.txt --hidden-import pystray._win32 --name DGCloakVPN cloak_ovpn.py`.
`version_info.txt` — версионный ресурс exe (описание, версия 1.0, © 2026 Dan Gorodchikov, ru-RU/en-US).
Результат: `dist\DGCloakVPN.exe` (сам запрашивает UAC). `--onefile` иногда вызывает ложные срабатывания антивирусов — тогда собирать `--onedir`.

## Известные проблемы и допущения

- **Нет автотестов; код писался и проверялся итеративно на машине пользователя.** Автор кода (ИИ) не мог запускать Windows-часть. Среда агента, скорее всего, Linux: tkinter-окно, `route.exe`, `tasklist`, `ctypes.windll` там не работают. Чистую логику (разбор состояний, формирование аргументов, `load_data`) лучше выносить в тестируемые функции.
- **Открытая проблема:** на ряде серверов, созданных Amnezia (AWS Lightsail), через ≈20 с после `CONNECTED` приходит `Connection reset by peer`
  от локального `ck-client` и начинается реконнект (OpenVPN при этом переподключается за ≈2 с и каждый раз получает новый адрес туннеля). На других серверах всё стабильно.
  Причина не установлена (сервер, сеть до него или Cloak). Клиентской ошибкой, по имеющимся данным, не является. Сначала проверять серверную сторону и поведение на свежеразвёрнутом сервере (см. «Планы»).
- Часть защитной логики (`repair_loopback`, `STATE_RE`, `route_failed`, `state on all` вместо `--management-hold`) появилась в процессе отладки; она подтверждена логами пользователя, но пересматривайте осознанно.
- Флаги CLI Cloak (`-c -l -s -p -u`) взяты из знаний ИИ и подтверждены работой; при обновлении Cloak сверяться с `ck-client -h`.
- Нет логина/пароля, нет шифрования секретов (их в `data.json` и нет), нет автозапуска и автоподключения при старте.

## Правила разработки

- Совместимость с Python 3.8+. Зависимости минимальные (stdlib + pystray + Pillow); новые добавлять осознанно.
- Не вызывать tkinter из рабочих потоков; всё через `self.ui`.
- Новые сообщения пользователю — по-русски, в лог — через `self.say`.
- Не менять формат `data.json` без обратной совместимости (пользовательские профили лежат в `%APPDATA%\DGCloakVPN\data.json`).
- Любые изменения запуска процессов/маршрутов осторожно: ошибки оставляют систему без рабочей сети до перезагрузки. Не убивать `openvpn.exe` жёстко без необходимости.
- Не коммитить: `data.json`, `*.ovpn`, конфиги Cloak, ключи, логи (логи содержат имена/IP серверов).

## Планы (по убыванию приоритета)

1. **Структура и качество:** разнести `cloak_ovpn.py` на модули (конфиг/профили, запуск процессов, сетевые утилиты, GUI, трей), вынести построение аргументов Cloak/OpenVPN в чистые функции и покрыть тестами; CI на GitHub Actions (`windows-latest`: `py_compile`, сборка exe).
2. **Клиент:** пароль на management-порт; поддержка `auth-user-pass`; автоподключение при старте; импорт клиентского пакета (`.ovpn` + `ckclient.json`) одной кнопкой; переключение профиля без ручного отключения.
3. **Серверное management-приложение** (замена Amnezia), развёртывание и управление OpenVPN over Cloak на Linux по SSH. Принятые решения:
   - Целевые ОС: Ubuntu 24.04 LTS и 26.04 LTS; **без Docker** (пакет OpenVPN, `ck-server`, сервисы systemd).
   - Параметры SSH (хост, порт, пользователь, ключ/пароль/ssh-agent) **настраиваемые, ничего не зашито**. Приложение не должно менять конфигурацию/порт SSH и не может «запирать» пользователя на сервере.
   - Пользователь = сертификат OpenVPN + UID Cloak: создание, отзыв, лимиты (срок/трафик/скорость), выгрузка клиентского пакета.
   - Статус, обновление, удаление, резервные копии конфигов перед изменениями; сначала аудит (только чтение), потом изменения.
   - У пользователя нет доступа к консоли боевых серверов (AWS Lightsail, firewall только TCP 443 и SSH). Разрабатывать и тестировать **только на отдельном тестовом VPS** со снапшотами; боевые серверы не трогать.
   - Перед реализацией сверяться с актуальной документацией Cloak и OpenVPN, а не с памятью.
