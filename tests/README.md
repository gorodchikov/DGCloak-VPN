# Тестовая система DGCloakAdmin

Два слоя тестирования:

| Слой | Где | Что | Когда |
|---|---|---|---|
| **Авто** | `tests/*.py` | быстрые, безопасные, повторяемые проверки | после каждого изменения |
| **Ручной** | `docs/test-plan.md` | деструктивные и долгие сценарии (деплой с нуля, сброс, откат VM, перезагрузка, клиент) | перед релизом / новым дистрибутивом |

## Файлы

- `labs.json` — **матрица стендов**: имена в реестре, дистрибутив, ожидаемый fw-бэкенд и `deployed`, флаги `auto`/`prod`. Единый источник правды о стендах.
- `lib.py` — каркас: песочница APP_DIR (реальный `data.json` не трогается), `check()/info()/finish()`, tkinter-помощники (`pump`, `sel`, `tab`, `jrnl`), доступ к реальному реестру (`real_srv`) и матрице (`labs`, `supported_os`).
- `matrix.py` — смоук по всем `auto`-стендам: SSH+sudo, дистрибутив, fw-бэкенд, `deployed`, реестр=реальность, покрытие карты `supported`. **Read-only** — безопасен на проде.
- `logtest.py` — журналы/каналы лога: deploy/users, verbose, очистка/копирование, переключение серверов, чужая операция, fw-строки на живой лабе.

Запуск:

```
python tests\matrix.py     # ~1-2 мин, все стенды с auto=true
python tests\logtest.py    # ~30 с, локальная часть + одна живая лаба
```

Код возврата: `0` — всё зелёное, `1` — были FAIL (годится для CI-хука).

## Правила для новых тестов

1. Только через `lib.py`: песочница настроена при импорте — App создаётся `make_app()`, окна невидимы.
2. Реальный `data.json` — read-only (`real_data()`, `real_srv()` возвращают копии).
3. На стендах с `prod: true` — никаких мутаций: только `detect.sh`, `probe.sh`, `fw-manage.sh ports`, `cat`, `ls`, `systemctl is-active`.
4. Каждая проверка — один `check("короткое имя", условие, детали)`. Детали печатаются только при FAIL и при ручном просмотре.
5. Тест не должен зависеть от порядка запуска и оставлять мусор на серверах (если что-то открыл — закрой: см. D-фазу logtest с портом 18088).

## Добавление дистрибутива в матрицу поддержки

1. Подними VM (снапшот «чистый») и заведи сервер в админке.
2. Добавь запись в `labs.json` (`distro`, `auto: true`; `fw`/`deployed` пока `null` — matrix покажет факт).
3. Расширь `supported` в `cloak_admin.py::_step_audit` — иначе деплой будет просить подтверждение.
4. `python tests\matrix.py` → M2/M3/M7 зелёные = SSH и детект работают.
5. Ручной блок **B** из `docs/test-plan.md` на новом дистре (полный деплой).
6. Если прошло — проставь в `labs.json` реальные `fw`/`deployed`, допиши дистрибутив в диалог `supported`-предупреждения и `docs/test-plan.md` (блок B).

## Добавление новой фичи

- Новая логика лога/каналов → чек в `logtest.py`.
- Новый серверный скрипт или поведение на всех бэкендах → чек в `matrix.py` (поле в `labs.json` при необходимости).
- Деструктивное/долгое → новый пункт в `docs/test-plan.md` + запись в «Найдено» при находке.
